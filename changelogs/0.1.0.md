# Changelog of 0.1.0

First stable release of the 0.1.0 line.

The repository was reinitialized at `0.1.0-dev2`, so this entry covers the
whole line at once and supersedes the `0.1.0-dev1` through `0.1.0-dev5`
notes. Work from the `0.0.1-alpha` series that carried over is listed here
too; that history is kept on the `legacy` branch.

## Added

### Worlds and simulation

- Every world runs on its own actor thread. Mutation inside a world - block
  placement and breaking, ticking, liquids, entities, movement, combat,
  effects, inventory changes, world local broadcasts - is sequential within
  that world and separate worlds run fully in parallel.
- Player and entity operations validate the target's current world
  membership and a binding epoch before applying, so a task queued against
  a world a player has since left produces no side effects instead of a
  stale mutation.
- Transactional world updates: mutable world access is expressed as a
  `WorldTx` handed to work running on the owning actor.
- Public handles - `World`, `PlayerRef`, `EntityRef` - over a unified
  player/entity registry, so callers operate through safe references
  instead of reaching into runtime internals.
- World management API on the server, plus `/world` commands to create,
  load, unload and delete worlds at runtime.
- Persistent block and tile writes moved off the world actor thread, so
  routine disk I/O no longer stalls simulation.
- A world level chunk service that deduplicates expensive generation work
  across sessions and bounds its workers.

### Chunks and terrain

- Reworked overworld generator with terrain noise interpolated once per
  column.
- Chunk sections stored as a palette plus a per block index with the block
  palette held in interned, flat tables.
- Light engine: server side light level computation for blocks and sky.
- Schema driven chunk block state upgrader with versioned upgrade steps
  applied on chunk load.
- Liquid engine with vanilla style flow, ticked every 5 ticks to match the
  vanilla rate.

### Networking

- Protocol encryption, enabled by default.
- Real Microsoft OIDC/RS256 login verification, replacing a check against
  the wrong key that had been silently rejecting genuine Xbox authenticated
  players. Includes live discovery/JWKS lookups and a from scratch RSA
  signature verifier.
- Each connected session has its own outbound queue and writer thread, so a
  slow or stalled client can no longer block a world's simulation or
  another player's delivery. Batches stay adjacent on the wire, a graceful
  disconnect drains what is already queued, and a queue that fills aborts
  that one session rather than dropping a packet silently.
- The NetherNet server identity key is persisted across restarts.
- Support for 1.26.50.

### Gameplay

- Block breaking timed from block hardness and tool speed, synchronized
  with server authoritative clients and scoped to the owning world.
- Entities: hostile mob melee attack with line of sight, per dimension
  attributes and a despawn policy.
- Projectiles.
- Potions, including splash and lingering variants, carrying per meta
  effect data.
- Status effects with durations, levels and particle colours.
- Enchantments.
- Item drop entities on block breaks and inventory drops with drop and
  pickup working across every input path.
- Note block and jukebox interactions.

### Public API packages

- Bossbar, title and scoreboard.
- Typed sound and particle packages.
- Skin package with serialized skins built from it.
- Chat channel package; sessions subscribe to global chat.
- Custom items, blocks, entities and enchantments registered through
  process wide free functions.

### Server and tooling

- Configuration loaded from `vedrock.toml`.
- Event bus with typed contexts and priority ordered handlers, dispatched
  for player, block, item, entity, combat, effect and world events.
- Tick scheduler with delayed and repeating tasks.
- Resource pack distribution and server driven modal forms.
- Crash report writer.
- `/status` reports memory usage.
- Localization for Spanish, French, German, Turkish and Russian with
  Crowdin integration; startup and world loading logs localized.
- Logger shows thread origin and time only stamps.
- A large set of deterministic concurrency tests covering per world
  isolation, world switch and epoch correctness and outbound delivery
  ordering and overflow.

## Performance

The chunk and palette layer was largely rewritten:

- Chunks cached as wire bytes instead of decoded columns.
- Sealed palette tables shed their spare capacity.
- The biome index array is skipped for single biome chunks.
- Generated terrain is written a column at a time.
- The chunk generation pool is sized to the machine, the sweep window to
  the pool, and the number of columns in flight is bounded.
- Larger chunk batches sent with a shorter pause.
- The boot allocation peak is returned to the OS.

## Changed

- `Hub` is no longer where gameplay executes. It is a lifecycle and lookup
  surface - session registry, world registry, cross world lookup and global
  configuration - not a shared actor every mutation passes through.
- Global admin state (difficulty, whitelist, operator status) moved from a
  job queue to direct, explicitly locked methods on `Hub`.
- Inventory split out of `item` into its own package; block items moved
  into the block package.
- Gamemode, damage source and tuple returns replaced with typed values.
- The encryption handshake is built on `crypto.ecdsa`; Vedrock's own
  OpenSSL bindings are gone.
- `effect` returns a rejected `AddResult` instead of panicking on invalid
  input.
- Client supplied input is bounded across the board: item stack request
  slots and amounts are validated, chat, sign and book text is bounded,
  block actions are capped per player auth input, unverified account ids
  are dropped from offline logins, and movement that has not converged to a
  server issued teleport is rejected.
- bedrock-v dependencies resolve under `bedrock_v/` following vpm org
  support. Requires `protocol >= v2.0.1`.
- Pinned V compiler updated.

## Fixed

- Listeners were closed while `accept_loop` was still using them.
- Chunks streamed in a square rather than the circular radius the client
  keeps; columns released before delivery were never retried, and dropped
  deliveries were not resent.
- Delivered packets were left occupying outbound queue slots.
- Tick overrun warnings fired when tick work was within budget.
- A world's clock resynced past what had actually been simulated.
- Chunk generation memory growth and a world loading freeze; concurrent
  generation is capped to one in flight batch per session.
- Persistence stalls could freeze worlds or shutdown.
- Block placement and breaking through `InventoryTransactionPacket`.
- A divorced copy of the player was registered into the world entity
  registry.
- Unauthenticated xuid/uuid claims were trusted for save key and grant
  matching.
- Several cross world packet leaks where an update in one world reached
  every connected player regardless of the world they were in.
- The command packet builder returned a value instead of a pointer, so an
  asynchronous writer thread could read a stack variable that no longer
  existed.
- An outbound writer thread that never exited when a session with nothing
  queued was aborted, leaking a thread per disconnect.
- A race between a session's pre activation direct writes and the outbound
  queue taking over, which could write a packet twice or out of order.
- Unavailable LAN discovery port is now tolerated.
- Obsidian uses the Bedrock hardness, and cobwebs require a tool.

## Removed

- Nether portals and the in tree plugin system did not carry over from the
  0.0.1-alpha series. Both remain on the `legacy` branch.
- The first run setup wizard and the Docker images are likewise gone, as
  are the vdocs committed into the tree - documentation now lives in
  vedrock-docs and is deployed from there.

## Upgrading

Dependencies now install under `~/.vmodules/bedrock_v/`. Remove the old top
level `protocol`, `nbt`, `nethernet` and `webrtc` copies before building -
keeping both layouts in one build makes V register each module twice and
reject its own types.
